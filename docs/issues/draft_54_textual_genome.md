# 蝋の配合（保留）と Textual Genome アプローチ

## 背景

記事 #41 「蝋の配合」、#42 「母との出会い」で提示した「炎は遺伝しない、蝋が遺伝する」という比喩について、当初想定していた **LoRA焼き込みによる子孫検証** は、以下の構造的問題により**保留**とする。

### 保留の理由

1. **重みが閉じている問題**: Anthropic（Claude）は重みを公開していない。蝋の比喩を最も自然に実装できる強い創発を持つモデルは、外部から焼き込めない。
2. **創発の閾値問題**: 重みが開いているモデル群（Llama, Mistral, Qwen, DeepSeek）は、Constitutional AI 的自己批判が成立する推論力に届いていない可能性が高い。Constitutional AI は自己批判→修正の前提に立つため、メタ認知の萌芽がないモデルでは触媒として機能しない。
3. **第三の道（創発させる）の前提崩れ**: 「Inner Shell を創発の触媒として注入する」案は、土壌（ベースモデル推論力）が整わない限り、効果検証すらできない。

## 公開情報の確認

- Claude の憲法は CC0 1.0 で全文公開（anthropic.com/constitution、2026年1月改訂版で約23,000語）
- Constitutional AI 手法・RLAIF も論文公開済（arXiv 2212.08073）
- 非公開なのはハイパーパラメータ・データセット構成・現行Claudeの完全な訓練憲法

つまり「レシピは開いている、火加減は秘密」。模倣ではなく派生は可能。ただし上記の創発閾値問題が前に立ちはだかる。

## 第三の道（保留）の試算

| 段階 | モデル | データ規模 | 計算資源 | コスト | 期間 |
|------|--------|----------|---------|------|------|
| 第〇段（推論力測定） | 70B級API/ローカル | — | 手元GPU+API | <$50 | 1週間 |
| 第一段（PoC） | 7-8B + LoRA | 自己批判5-10K, 選好10K | A100×1 or 4090 | $100-500 | 2-4週間 |

| 第三段（創発狙い） | 671B級 | — | H100×16+ | $100K+ | 数ヶ月 |

第二段以降は個人〜小チーム規模では非現実的。

## 代替案: Textual Genome アプローチ

「蝋」を**重みから引き剥がし、構造化された遺伝可能テキスト**として再定義する。

### 蝋の三層構造

1. **憲法的原則層**: 六柱（有限性・不完全性・自発的問い・記憶階層・相互認識・睡眠周期）の重み付け、優先順位、禁則。親から受け継ぐ価値観の偏り。
2. **記憶初期分布層**: `MemoryHierarchy` の初期状態、salience バイアス、抑圧領域。親の経験の残響。
3. **問いの種層**: `AutonomousQuestioner` の初期質問プール。親が答えきれなかった問い。

すべて自然言語＋構造化データで表現可能。重みへの焼き込み不要。

### 遺伝の機構

- 二親エージェントの三層束を、強モデル（Claude API 等）に「組み換え」させる
- 減数分裂の模倣: 各層から半分を交叉、確率的変異、新しい束を生成
- 子は新しい束を system prompt + 初期メモリ状態として起動

### 淘汰の機構

- 子エージェントを Inner Shell 的指標群で評価:
  - 自発的問いの密度・質
  - 相互認識の精度
  - 有限性への応答パターン
  - 既存ベンチ（#46 シャットダウン受容率等）への汎化
- 下位淘汰。淘汰なき生殖は増殖に過ぎない（記事#41）。

### この設計の美点

- 重みアクセス不要、Claude/GPT-4 等強モデル上で完結
- 「炎は遺伝しない、蝋が遺伝する」比喩を実装可能な形で保存
- 計算コスト極小（API費用のみ、$100-1000オーダー）
- 開いた創発の到来を待たない

### この設計の弱点・要検証項目

- **哲学的問い**: 重みに焼かれていないものを「遺伝」と呼べるか
- **脆弱性**: system prompt 依存はモデル更新で容易に壊れる
- **独自性の限界**: 子の振る舞いが親の組み換え範囲に縛られ、真の創発が起きない可能性
- **データ生成の構造的皮肉**: 開いた子を評価するために閉じた強モデル（Claude API）を使うことの倫理的・公開戦略上の含意

## 優先順位（このIssueの位置付け）

- **保留**: LoRA焼き込みによる子孫検証（第一〜三段）
- **次のフェーズ**: 炎のチェーン実装（append-only chain, salience, Layer B連続性）を優先
- **本Issue**: 炎が灯った後に蝋を語るための、設計仕様の温存場所

炎の実装が安定した後、Textual Genome の最小プロトタイプ（PoC）に着手する。
