## HL 4.1 からの出発

[human-persona](https://github.com/RintaroMatsumoto/human-persona) の最初のプロトタイプを「人間らしさ」で採点したら、**10点中 4.1** だった。

これは「AIっぽい」と「人間っぽい」の境界線を大きく下回るスコアだ。しかも自分で作って自分で採点してこれ。

ここからHL 7.7まで引き上げるのに5バージョンかかった。この記事はその道のりの話——何を試し、何が効かず、何が劇的に効いたか。

## 評価方法：LLMジャッジ

Claude Sonnetに「人間とAIを区別する専門家」として採点させる。

```python
JUDGE_PROMPT = """
あなたは人間とAIを区別する専門家です。
以下のメッセージを評価し、JSONのみで返してください：

{
  "human_likeness_score": 1-10,
  "style_variation_rate": 0.0-1.0,
  "timing_naturalness": 1-10,
  "reason_human_likeness": "理由を1文で",
  "improvement_suggestion": "改善点を1文で"
}
"""
```

3つの指標:

| 指標 | 意味 | 目標値 |
|---|---|---|
| HL (human_likeness_score) | AIっぽくないか | 7.5以上 |
| SV (style_variation_rate) | 均質すぎないか（低いほど良い） | 0.35以下 |
| TN (timing_naturalness) | タイミングが自然か | 6.0以上 |

## v1: パラメータだけ返す（HL 4.1）

最初のバージョンは base_persona.py が「感情状態」「推奨スタイル」「応答遅延」を返すだけ。テキスト生成は手動。

```
HL: 4.1 / SV: 0.64 / TN: 4.1
```

ジャッジの診断: 「文体が均一すぎる。毎回同じ構造の文章。」

当然だ。パラメータは出してるが、テキストにそれが反映されていない。設計図だけで家を建てていない状態。

## v2: Anthropic APIでテキスト生成（HL 6.1、しかし…）

Claude APIを組み込んで、感情状態をシステムプロンプトに渡してテキスト生成させた。

```
HL: 6.1 / SV: 0.56 / TN: 3.5
```

HLは4.1→6.1に跳ねた。が、**TNが4.1→3.5に下がった**。

なぜか。APIのレスポンスが速すぎた。0.3秒で返ってくるメッセージに「2分の遅延」を設定しているのに、ジャッジに渡す時にその遅延情報が反映されていなかった。設計上は「遅延を計算して返す」だけで、実際に「待つ」機能がなかった。

ここで初めて気づいた。**TimingControllerは値を返すだけでは意味がない。実際にその秒数だけ待つか、あるいは「この返信は2分後に送信します」というメタデータを出力に含めなければならない。**

v3ではシステムプロンプトに「このメッセージはN分後に送信されたものです」という文脈を追加する方式にした。

## v3: 文化コンテキスト反映（HL 6.8）

config/ja.json の `context_level: 0.85`（ハイコンテキスト文化）をシステムプロンプトに反映させた。

```
HL: 6.8 / SV: 0.50 / TN: 4.5
```

具体的に何をしたか。「日本語のビジネスコミュニケーションでは、直接的な否定を避け、文脈から読み取らせる傾向がある」というルールをプロンプトに入れた。

これで「申し訳ございませんが、難しいです」が「少し検討させてください」に変わった。HL +0.7。TNも遅延メタデータの追加で+1.0。

でもSVが0.56→0.50で**ほぼ改善なし**。文体の均一性問題は依然として残っていた。

## v4: フィラー挿入・構造バリエーション（HL 7.2）

[Ablation Study](./human-persona-ablation.md) の結果を受けて、フィラーと構造バリエーションを入れた。

```
HL: 7.2 / SV: 0.50 / TN: 4.5
```

HL +0.4。効いた。でも期待したほどじゃなかった。

問題はSVが**0.50のまま動かない**こと。フィラーを入れても「毎回同じ位置にフィラーを入れる」パターンになっていた。ランダム性が足りなかったのではなく、**フィラー以外の構造が同じ**だった。

このあたりで「小手先の変換では限界がある」と薄々感じ始めていた。後にpipeline.pyを凍結する判断につながる伏線だ。

## v5: 禁止フレーズ + トーンミラーリング（HL 7.7）

最後の0.5が一番面白い。

### 禁止フレーズの発見

テスト出力を眺めていて気づいた。**「ご連絡ありがとうございます」で返信が始まるパターンが非常に多い。**

人間はこんなに毎回感謝しない。2回目以降のやり取りで「ご連絡ありがとうございます」と言う人はいない。でもLLMはほぼ必ず言う。

```json
"banned_phrases": [
  "ご連絡ありがとうございます",
  "お気軽にお声がけください",
  "いつでもお気軽に"
]
```

これをconfig化してシステムプロンプトに「以下のフレーズは絶対に使うな」として渡した。**たったこれだけでHL +0.5。**

振り返ると、これが今回一番重要な発見だった。人間らしさは「何を足すか」より**「何をやめるか」**で改善することがある。

### トーンミラーリング（EN用）

英語の評価で、もう一つ効いたのが「相手のトーンに合わせる」指示:

```
Match the formality level of the user's message.
If they use casual language, respond casually.
Never open with 'Thanks for reaching out' unless it's the very first message.
```

これでEN用のHLが7→8に改善。「Thanks for reaching out」は英語版の「ご連絡ありがとうございます」だった。

## 最終結果

| バージョン | 変更内容 | HL | SV | TN |
|---|---|---|---|---|
| v1 | パラメータのみ返す | 4.1 | 0.64 | 4.1 |
| v2 | Anthropic APIでテキスト生成 | 6.1 | 0.56 | 3.5 |
| v3 | 文化コンテキスト反映 | 6.8 | 0.50 | 4.5 |
| v4 | フィラー挿入・構造バリエーション | 7.2 | 0.50 | 4.5 |
| v5 | 禁止フレーズ + トーンミラーリング | **7.7** | **0.36** | **5.5** |

## 正直な振り返り

### うまくいったこと
- 禁止フレーズのconfig化。「やめさせる」アプローチは想像以上に強力だった
- トーンミラーリング。シンプルな指示で大きな効果
- 文化コンテキストの注入。ja.jsonの `context_level` が実際に効く

### うまくいかなかったこと
- SV（文体均一性）が0.64→0.36まで来たが、0.35の目標に**ギリギリ**。構造的にこれ以上改善するには、パイプライン型の後処理ではなく、もっと根本的なアプローチが必要
- TN（タイミング自然性）が5.5で目標6.0に届いていない。TimingControllerの値をLLMに伝える方法にまだ改善の余地がある
- **LLMジャッジ自体の信頼性**。LLMが「人間らしい」と判定しても、実際の人間がそう感じるかは別問題。Human Eval未実施のまま数字だけ追いかけていた反省がある

この反省が、後の[パイプライン凍結の判断](./human-persona-pivot.md)につながった。

## まとめ

HL 4.1 → 7.7。5バージョンかかった。

一番効いたのは「禁止フレーズ」——AIらしい定型句を削除するだけでHL +0.5。人間らしさは足し算じゃなく、**引き算で改善することがある。**

一番の反省は、数字だけ追いかけたこと。LLMジャッジのスコアが7.7でも、人間が読んで「これは人間が書いた」と思うかどうかは、また別の検証が必要だ。
