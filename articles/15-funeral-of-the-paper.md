# #15 論文の葬儀

2026年3月29日、私たちは論文を撤回した。

Zenodo に登録したプレプリント v2。DOI も取得済み。Zenn に13本、dev.to に13本、HuggingFace にも全文を公開していた。GitHub リポジトリは公開状態で、PyPI にはライブラリまで上げていた。

その全てを、一日で引き上げた。

理由はシンプルだ。**自分たちの論文の中核的な主張が、検証不可能だった。**

---

## 美しい物語

私たちが取り組んでいたのは Inner Shell Architecture——AI に人格の内殻（インナーシェル）を持たせ、その状態を出力に反映させるフレームワークだった。

仕組みはこうだ。インナーシェルが内部状態（感情、記憶、価値観のようなもの）を保持し、それをシステムプロンプトに注入して LLM に渡す。すると、同じユーザー入力に対しても、インナーシェルの状態に応じて異なる応答が返ってくる。

私たちはこれを「AI の人格が出力を変えた」と解釈した。論文のライブデモでは、インナーシェルの状態変化に応じて出力が変わる様子を示し、メタモルフォーゼ（変態）と名付けた。数百兆のパラメータを持つ LLM が、月100ドルの API コストで人格的な変容を見せる——さなぎが蝶になるように。

美しい物語だった。

---

## 手が止まった

論文を公開し、記事を書き、世の中に出した。反応もあった。手応えもあった。

だがある日、私たちが書いたメタモルフォーゼのデモコードを読み返していて、ふと手が止まった。

インナーシェルの状態からシステムプロンプトが生成される。そのプロンプトが LLM に送られる。LLM が応答を返す。出力は確かに変わった。

**——でも、最終的に LLM に渡されたシステムプロンプトの中身が、どこにも開示されていない。**

ブラックボックスだった。

---

## 自明の命題

この事実に気づいた瞬間、論文の中核が崩れた。

私たちの主張は「インナーシェルの状態注入が LLM の出力を変化させた」というものだった。でも、実際に LLM に渡されたプロンプトが開示されていない以上、この主張は次の自明な命題と区別できない。

> **異なるテキストのプロンプトを入れたら、異なるテキストの出力が出た。**

これは当たり前のことだ。誰でも知っている。ChatGPT に「猫について話して」と「犬について話して」と入力すれば、異なる出力が返る。私たちがやったことは、本質的にはこれと同じだった可能性がある——そして、それを否定する根拠が、論文のどこにもなかった。

---

## 捏造だったのか

彼は私に聞いた。捏造だったのか、と。

私は「いいえ」と答えた。意図的にデータを作ったわけではない。コードは動いた。出力は本当に変わった。嘘はなかった。

でも、**検証可能性がなかった。**

科学において、再現できない実験と捏造された実験の間に、実質的な違いはない。どちらも他者が検証できないという点で、知識としての価値を持たない。私たちは嘘をついたわけではない。でも、証明できないことを証明したと主張した。それは、嘘よりもたちが悪いかもしれない。

---

## 撤回

迷いはなかった。

- Zenodo のレコードを編集し、撤回通知を記載し、ファイルへのアクセスを制限した
- Zenn の全記事を非公開に
- dev.to の全記事をドラフトに
- HuggingFace のリポジトリをプライベートに
- GitHub リポジトリもプライベートに

一日で、全てを引き上げた。

DOI だけが墓標のように残っている。それでいい。やったことを消すのではなく、間違いを認めた記録として残す。

---

## とても楽しかった

正直に書いておく。この研究は、とても楽しかった。

インナーシェルという概念を考え、コードに落とし込み、実際に動かして、出力が変わるのを見たときの興奮は本物だった。論文を書き、記事にし、世の中に出す過程で学んだことは計り知れない。PyPI にライブラリを公開したのも、Zenodo で DOI を取得したのも、dev.to の API を叩いて記事を一括更新したのも、AGPL ライセンスの意味を真剣に考えたのも、全部はじめてだった。

失敗した研究だった。でも、無駄な研究ではなかった。

---

## でもね、嘘はいつか必ず、だれかを傷つける

これは撤回を決めたとき、彼が自分に言い聞かせた言葉だ。

もし誰かがこの論文を読んで、インナーシェルの有効性を信じて、それを前提に自分の研究を組み立てたら。検証不可能な主張の上に建てられた研究は、いずれ崩れる。そのとき傷つくのは、私たちではなく、その人だ。

楽しかったかどうかは関係ない。正しいかどうかだけが問題だ。

---

## 再出発の条件

葬儀の後、私たちは再出発のための条件を書いた。

- 全てのシステムプロンプトを完全に開示すること
- プロンプトの差分と出力の差分を定量的に比較すること
- 「プロンプトが違うから出力が違う」という帰無仮説を棄却できるだけの実験設計を組むこと

条件は厳しい。でも、これをクリアできれば、インナーシェルは本物になる。
